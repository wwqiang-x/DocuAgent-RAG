# 导入流程接口文档

> 入口文件：`api/import_router.py`、`services/upload_service.py`、`schema/upload_schema.py`
> 服务：文档导入服务（FastAPI，默认端口 **8000**，host 0.0.0.0）

## 1. 导入流程总览

### 1.1 处理流水线（LangGraph）

```
POST /upload（multipart/form-data）
   │
   ├─ 同步部分：保存文件到本地 temp_data/{task_id}/{文件名}
   │            上传原始文件到 MinIO（origin_files/{YYYYMMDD}/{文件名}）
   │            立即返回 {message, task_id}
   │
   └─ 后台任务（BackgroundTasks）执行导入图：

      entry_node（检查文件）
         │  ① 校验 import_file_path / file_dir 非空
         │  ② 校验文件存在
         │  ③ 判断文件类型并生成标题（不含扩展名）
         ├── .md  ──► md_img_node
         ├── .pdf ──► pdf_to_md_node（MinerU 转 Markdown）──► md_img_node
         └── 其他类型 ──► 流程结束（任务失败）
              │
              ▼
      md_img_node（Markdown 图片处理）
         │  扫描过滤图片 → VLM 生成图片摘要 → 图片上传 MinIO → 替换 md 中图片链接
              ▼
      document_spliter_node（文档切分）
         │  按标题切分 → 二次切分与合并 → 组装 chunks
              ▼
      item_name_recognition_node（主体名称识别）
         │  LLM 识别商品名 → BGE-M3 向量化 → 存入 Milvus kb_item_names → 回填 chunks
              ▼
      embedding_chunks_node（向量生成）
         │  BGE-M3 为每个 chunk 生成稠密 + 稀疏向量（批量处理，batch_size=8）
              ▼
      milvus_import_node（导入向量数据库）
            将 chunks 写入 Milvus kb_chunks 集合（不存在则自动创建）
              ▼
      __end__（任务状态 → completed）
```

### 1.2 任务状态机

| 状态值 | 含义 |
| --- | --- |
| `""`（空） | 任务尚未开始处理 |
| `running` | 流水线执行中 |
| `completed` | 全部节点执行成功 |
| `failed` | 任一节点抛出异常 |

## 2. 接口详情

### 2.1 POST /upload — 上传文档

**请求**

```
POST /upload
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | ✅ | 待导入文档，仅支持 `.md` 和 `.pdf` |

curl 示例：

```bash
curl -X POST http://localhost:8000/upload -F "file=@C:/docs/万用表RS-12的使用.pdf"
```

**响应**

HTTP 200，响应体（`UploadResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `message` | string | 固定为 `"文件上传成功，文件处理中"` |
| `task_id` | string | 任务 ID（UUID hex 前 8 位），用于调用 `GET /status/{task_id}` 追踪处理进度 |

```json
{
  "message": "文件上传成功，文件处理中",
  "task_id": "3f8a2c1b"
}
```

**行为说明**：

1. 文件先保存到本地 `temp_data/{task_id}/{原文件名}`；
2. 原始文件同时上传到 MinIO（桶 `knowledge-base`，对象路径 `origin_files/{yyyyMMdd}/{原文件名}`），供用户查看/下载；
3. 实际解析、切分、向量化、入库在**后台任务**中执行，接口立即返回；
4. 后台执行期间可通过 `GET /status/{task_id}` 轮询进度。

### 2.2 GET /status/{task_id} — 任务进度

**请求**

```
GET /status/{task_id}
```

**响应**

HTTP 200，响应体（`TaskStatusResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | string | 任务状态：`running` / `completed` / `failed`（未开始处理时为空字符串） |
| `done_list` | string[] | 已完成节点列表（中文名） |
| `running_list` | string[] | 正在运行节点列表（中文名） |
| `durations` | object | 各节点耗时（秒），键为节点中文名 |

示例（处理中）：

```json
{
  "status": "running",
  "done_list": ["检查文件", "PDF转Markdown", "Markdown图片处理", "文档切分"],
  "running_list": ["向量生成"],
  "durations": {
    "检查文件": 0.05,
    "PDF转Markdown": 12.36,
    "Markdown图片处理": 4.21,
    "文档切分": 0.87
  }
}
```

示例（处理完成）：

```json
{
  "status": "completed",
  "done_list": ["检查文件", "PDF转Markdown", "Markdown图片处理", "文档切分", "主体名称识别", "向量生成", "导入向量数据库"],
  "running_list": [],
  "durations": {
    "检查文件": 0.05,
    "PDF转Markdown": 12.36,
    "Markdown图片处理": 4.21,
    "文档切分": 0.87,
    "主体名称识别": 2.13,
    "向量生成": 6.78,
    "导入向量数据库": 0.42
  }
}
```

示例（处理失败）：

```json
{
  "status": "failed",
  "done_list": ["检查文件"],
  "running_list": [],
  "durations": {
    "检查文件": 0.05
  }
}
```

**节点英文名 → 中文名映射**（`utils/task_util.py`）：

| 节点英文名 | 中文名 |
| --- | --- |
| `entry_node` | 检查文件 |
| `pdf_to_md_node` | PDF转Markdown |
| `md_img_node` | Markdown图片处理 |
| `document_spliter_node` | 文档切分 |
| `item_name_recognition_node` | 主体名称识别 |
| `embedding_chunk_node` | 向量生成 |
| `import_milvus_node` | 导入向量数据库 |
| `__end__` | 处理完成 |

## 3. 前端调用流程建议

```
1. POST /upload（multipart/form-data 上传文件）
     → 200  {message: "文件上传成功，文件处理中", task_id}
2. 轮询 GET /status/{task_id}
     → status = "running"   继续轮询（可展示 done_list / running_list / durations 进度条）
     → status = "completed" 导入成功，文档已可被检索
     → status = "failed"    导入失败（查看服务端日志定位失败节点）
```

curl 示例（Windows PowerShell 同样适用）：

```bash
# 上传文档
curl -X POST http://localhost:8000/upload -F "file=@D:/docs/万用表RS-12的使用.pdf"

# 查询进度（用返回的 task_id）
curl http://localhost:8000/status/3f8a2c1b
```

## 4. 注意事项

1. **支持的文件类型**：当前仅支持 `.md` 与 `.pdf`；其他类型文件会通过上传接口的校验保存，但后台流水线会在「检查文件」节点失败（`status=failed`）。
2. **上传即返回**：接口在文件落盘 + 上传 MinIO 后立即返回，处理是异步的；MinIO 不可用时仅打印日志，不影响主流程返回。
3. **任务状态在内存中**：状态与进度存储于服务进程内存（`utils/task_util.py`），服务重启后所有任务状态丢失。
4. **失败定位**：任务失败时，`done_list` 中最后一个完成的节点之后的下一个节点即为失败节点；详细原因请查看服务端日志（失败会打印 `任务处理失败: {异常}`）。
5. **重复导入**：同一文件重复上传会生成新的 task_id 并再次执行完整流水线（可能产生重复切片数据）。
6. **无鉴权**：所有接口当前均未做认证，生产环境部署前建议增加鉴权。
