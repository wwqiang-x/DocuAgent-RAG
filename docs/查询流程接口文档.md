# 查询流程接口文档

> 入口文件：`api/query_router.py`、`services/query_service.py`、`schema/query_schema.py`
> 服务：智能查询服务（FastAPI，默认端口 **8001**，host 0.0.0.0）

## 1. 查询流程总览

### 1.1 处理流水线（LangGraph）

```
POST /query
   │
   ▼
item_name_confirmed_node（确认问题产品）
   │  ① LLM 提取商品名 + 改写查询（结合 Mongo 历史上下文）
   │  ② 商品名与 Milvus kb_item_names 集合对齐：
   │     高置信 → item_names 确定；中置信 → 生成询问候选 answer；
   │     无法理解 → 生成"抱歉"answer
   ├─── state 已有 answer ──► answer_output_node（直接回复）
   │
   └─── 无 answer ──► multi_search（三路并行召回）
                        ├── hybrid_vector_search_node   向量混合检索（原查询，kb_chunks）
                        ├── hyde_vector_search_node     HyDE 假设性文档检索
                        └── web_mcp_search_node         网络搜索（DashScope MCP WebSearch）
                              │  join_node（汇聚）
                              ▼
                        rrf_merge_node（RRF 融合两路向量检索结果）
                              ▼
                        reranker_node（BGE-Reranker 重排序 + 断崖监测）
                              ▼
                        answer_output_node（LLM 生成答案 + 保存 Mongo 历史）
```

### 1.2 两种调用模式

| 模式 | `is_stream` | 返回时机 | 前端获取答案方式 |
| --- | --- | --- | --- |
| 同步模式 | `false`（默认） | 流水线执行完毕后一次性返回 | 直接读取响应体 `answer` 字段 |
| 流式模式 | `true` | 立即返回任务 ID，后台执行 | 用 `task_id` 连接 `GET /stream/{task_id}` 接收 SSE 事件 |

---

## 2. 接口详情

### 2.1 POST /query — 提交查询

**请求**

```
POST /query
Content-Type: application/json
```

请求体（`QueryRequest`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `query` | string | ✅ | 查询内容（用户问题） |
| `session_id` | string | ❌ | 会话 ID；不传则服务端自动生成一个 UUID 并在响应中返回 |
| `is_stream` | boolean | ❌ | 是否流式返回，默认 `false` |

请求示例：

```json
{
  "query": "RS-12数字万用表如何测量电阻",
  "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
  "is_stream": true
}
```

**响应 — 同步模式（`is_stream=false`）**

HTTP 200，响应体（`QueryResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `message` | string | 固定为 `"查询成功"` |
| `session_id` | string | 会话 ID |
| `answer` | string | LLM 生成的最终答案 |

```json
{
  "message": "查询成功",
  "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
  "answer": "测量电阻的步骤如下：1. 将功能转盘置于 Ω 档位……"
}
```

**响应 — 流式模式（`is_stream=true`）**

HTTP 200，响应体（`StreamSubmitResponse`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `message` | string | 固定为 `"正在查询"` |
| `session_id` | string | 会话 ID |
| `task_id` | string | 任务 ID，前端用此 ID 建立 SSE 连接（见 2.2） |

```json
{
  "message": "正在查询",
  "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
  "task_id": "3f8a2c1b9d04"
}
```

### 2.2 GET /stream/{task_id} — 流式结果（SSE）

> ⚠️ 必须先调用 `POST /query`（`is_stream=true`）创建事件队列，再连接本接口；
> 若队列不存在，连接会立即结束。

**请求**

```
GET /stream/{task_id}
Accept: text/event-stream
```

**响应**：`text/event-stream`，服务端推送以下三种事件：

| 事件类型 | 触发时机 | data 结构 |
| --- | --- | --- |
| `progress` | 每个图节点开始/结束时 | `{"status": "processing", "done_list": [...], "running_list": [...], "durations": {...}}` |
| `delta` | LLM 流式输出期间（每个增量片段） | `{"answer": "<增量文本>"}` |
| `final` | 答案生成完毕 | `{"answer": "<完整答案>"}` |

- `done_list` / `running_list` 为中文节点名列表；`durations` 为 `{节点中文名: 耗时(秒)}`。
- 前端把 `delta` 事件中的 `answer` 片段依次拼接即为流式答案；收到 `final` 表示本次查询结束。
- 客户端断开连接后，服务端自动清理该任务的 SSE 队列。

SSE 原始报文示例：

```
event: progress
data: {"status": "processing", "done_list": ["确认问题产品"], "running_list": [], "durations": {"确认问题产品": 1.23}}

event: delta
data: {"answer": "测量电阻的"}

event: delta
data: {"answer": "步骤如下……"}

event: final
data: {"answer": "测量电阻的步骤如下……"}
```

### 2.3 GET /status/{task_id} — 任务进度

**请求**

```
GET /status/{task_id}
```

**响应**

> ⚠️ **注意**：当前代码中该接口为**占位实现**，返回的是写死的示例数据（见下），
> 尚未接入真实的 `task_util` 任务状态。预期结构与导入服务的
> `GET /status/{task_id}`（`TaskStatusResponse`）一致：`status` / `done_list` / `running_list` / `durations`。

当前实际返回：

```json
{
  "status": "processing",
  "done_list": ["entry_node", "document_spliter"],
  "running_list": ["embedding_chunks"],
  "durations": {
    "entry_node": 0.5,
    "document_spliter": 2.3
  }
}
```

### 2.4 GET /history/{session_id} — 会话历史

**请求**

```
GET /history/{session_id}
```

**响应**（`HistoryResponse`）：返回该会话最近 **20** 条消息（MongoDB `chat_message` 集合，按时间倒序）。

```json
{
  "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
  "items": [
    {
      "_id": "66d1e2f3a4b5c6d7e8f9a0b1",
      "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
      "role": "user",
      "text": "RS-12数字万用表如何测量电阻",
      "rewritten_query": "RS-12数字万用表如何测量电阻？",
      "item_names": ["RS PRO RS-12 数字万用表"],
      "ts": 1754935260.123
    },
    {
      "_id": "66d1e2f3a4b5c6d7e8f9a0b2",
      "session_id": "3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c",
      "role": "assistant",
      "text": "测量电阻的步骤如下：……",
      "rewritten_query": "RS-12数字万用表如何测量电阻？",
      "item_names": ["RS PRO RS-12 数字万用表"],
      "ts": 1754935265.456
    }
  ]
}
```

`items` 中每条记录（`HistoryItem`）字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `_id` | string | MongoDB 文档 ID |
| `session_id` | string | 会话 ID |
| `role` | string | 角色：`user` / `assistant` |
| `text` | string | 消息内容 |
| `rewritten_query` | string | 改写后的查询（仅查询轮生成） |
| `item_names` | string[] | 识别出的商品名列表 |
| `ts` | float | 时间戳（秒） |

### 2.5 DELETE /history/{session_id} — 清空历史

**请求**

```
DELETE /history/{session_id}
```

**响应**：删除该会话在 MongoDB 中的全部消息。

```json
{
  "message": "历史记录去除成功",
  "deleted_count": 15
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `message` | string | 提示信息 |
| `deleted_count` | integer | 实际删除的消息条数 |

## 3. 前端调用流程建议

**同步模式**（适合短答案 / 调试）：

```
POST /query  {query, session_id}  →  200  {message, session_id, answer}
```

**流式模式**（推荐，适合正式交互）：

```
1. POST /query  {query, session_id, is_stream: true}
     → 200  {message: "正在查询", session_id, task_id}
2. GET /stream/{task_id}（EventSource）
     → 依次接收 progress → delta × N → final
3. （可选）GET /history/{session_id} 获取历史消息
4. （可选）DELETE /history/{session_id} 清空会话
```

curl 示例（Windows PowerShell 同样适用）：

```bash
# 同步查询
curl -X POST http://localhost:8001/query -H "Content-Type: application/json" -d "{\"query\":\"万用表如何测电阻\",\"is_stream\":false}"

# 流式查询（先提交）
curl -X POST http://localhost:8001/query -H "Content-Type: application/json" -d "{\"query\":\"万用表如何测电阻\",\"is_stream\":true}"

# 再监听 SSE（用上一步返回的 task_id）
curl -N http://localhost:8001/stream/3f8a2c1b9d04

# 获取历史
curl http://localhost:8001/history/3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c

# 清空历史
curl -X DELETE http://localhost:8001/history/3f8a2c1b-9d04-4e5a-8b7c-6d5e4f3a2b1c
```

## 4. 注意事项

1. **SSE 时序**：先 `POST /query`（stream 模式）再连接 `/stream`，两者之间间隔不宜过长（队列在内存中，任务结束后数据会丢失）。
2. **会话连续性**：多轮对话请保持同一个 `session_id`，历史消息会参与商品名提取与查询改写。
3. **商品名对齐失败**：当系统无法唯一确定问题涉及的商品时，`answer` 会是澄清性反问（如"请问你是在询问以下内容吗：[…]"），前端可直接展示，无需二次处理。
4. **状态接口**：查询服务的 `GET /status/{task_id}` 目前为占位实现，进度信息请以 `/stream` 的 `progress` 事件为准。
5. **无鉴权**：所有接口当前均未做认证，生产环境部署前建议增加鉴权。
